# Design adoption audit: @hyprsh/design v0.11.0 in the Kestrel web UI

An inventory of hand-built UI in `web/src` set against the components `@hyprsh/design` v0.11.0 provides. It records what is there and what the design docs say. The Decision column and the decisions under Open questions came later, from the review that ADR 0017 (`docs/adr/0017-kestrel-adapts-to-hyprsh-design.md`) records.

## Scope, sources and method

- **Scope:** every `.ts` and `.tsx` file under `web/src` on `main`, excluding `*.test.*`, the test helpers in `web/src/test/` and the generated `web/src/api/schema.gen.ts`.
- **Kestrel commit:** `8418032` (`main` HEAD). Domain terms follow `GLOSSARY.md`.
- **Design library:** `hyprsh/design` tag `v0.11.0`, commit `dd71461625ad07aa48b281ce4d39201305022cc6`, read from a shallow clone (nothing in it was run). `web/node_modules/@hyprsh/design/dist` (version 0.11.0) was used to cross-check; the first lines of the Table, Entity, Collapse, Skeleton and Note docs match the repo READMEs.
- **Citation forms:**
  - `D:<Name>` means `project/components/<Name>/README.md` in the tag (the component doc). `src/<Name>.d.ts` and `src/<Name>.css` mean `project/components/src/<Name>.d.ts` and `.css`.
  - "AGENTS.md index" means `dist/AGENTS.md`. It is generated at package time (`scripts/package.mjs:9`, `scripts/docs.mjs`) and is not a file in the tag; its component list is built from the same component docs. Rules quoted from it are also in `docs/getting-started.md`, `project/README.md` and `project/guidelines.md` where noted.
  - Other design paths are repo paths in the tag (`docs/getting-started.md`, `project/README.md`). Kestrel paths are repo-relative with line ranges.
- **Method:** each file was read; then `grep` passes covered raw `<svg>`, `<img>`, `<button>`, `<a>`, `<code>`, `<label>`, `<pre>`, `window.confirm`, `fetchNextPage`, "Loading", `Spinner`, `Skeleton`, `animate-`, and a parse of every design-component JSX tag that carries `className`. A row is a pattern; identical repeats are grouped into one row listing every location.
- **Verdicts (exactly one per row):**
  - `fits as-is`: a documented component covers the pattern with no prop beyond plain use.
  - `fits with a prop or variant`: a documented prop or variant (named and cited) covers it.
  - `gap: no component covers it`. For a design component that Kestrel restyles through `className`, `gap` means the doc and `.d.ts` name no prop or variant for that change.
- **Skipped:** pure layout utilities (flex, grid, gap, width, overflow, `self-start`, `ml-auto`, `order-*`, `col-*`, `shrink-0`) on otherwise unstyled wrappers; plain uses of design components; text-colour-only classes (`text-amber-900`, `text-red-900`) and typography classes; plain-text empty or status lines with no chrome (for example `web/src/library/EpisodeMatrix.tsx:109`); screens that render nothing while loading (the Library list, Requests, Log, Pipeline). The `Menu`-based and `Table`-based code that already uses the design's parts is not listed. Width and margin utilities passed to design components are listed in one grouped table.

## NavRow and KestrelLogo

### NavRow (`web/src/ui.tsx:6-21`)

- **What it renders:** `li` with `data-nav="<scope>-<index>"`, `aria-current="true"` on the row whose index equals `sel`, `onClick={onSelect}`, and classes `cursor-pointer` plus `bg-gray-alpha-200` (cursor row) or `hover:bg-gray-alpha-100`; the caller adds the rest through `className`.
- **Behaviour it serves:** `useListNav` (`web/src/keys.ts:40,68`) scrolls `[data-nav="<scope>-<sel>"]` into view; `NavRow` is the visual and ARIA half of the j/k cursor.
- **Call sites (9, in 5 files):** `web/src/grabs/GrabRow.tsx:81` (and its `li` fallback at line 85); `web/src/requests/RequestRow.tsx:59`; `web/src/upcoming/Upcoming.tsx:207`, `:303`, `:314`, `:351`; `web/src/overview/NeedsAttention.tsx:152`; `web/src/overview/ComingRecent.tsx:37`, `:64`. Their `className` adds padding (`px-3 py-2`, `px-4 py-3`, `py-2 pr-3 pl-9`, `pl-16`), flex layout, `relative`, and in Upcoming the arbitrary selector `[&[aria-current=true]_.rail-dot]:ring-transparent`.
- **Same visual, not using NavRow:** the Library list row (`web/src/library/Library.tsx:254`) repeats `bg-gray-alpha-200` / `hover:bg-gray-alpha-100` on a `role="option"` div. Kestrel's own use of the design's cursor state: `Table.Row current` at `web/src/log/Log.tsx:196`, `web/src/log/Log.tsx:270` and `selected` at `web/src/library/ManualSearch.tsx:272`.
- **Design docs on the same job:** `D:Table`, "Selected and current rows": `current` "sets `aria-current="true"` ... both use the same tint as a highlighted menu item and a 2px marker on the first cell ... `current` for the keyboard cursor of a j/k list". `src/Table.css:55-59` gives `.is-current` cells `background-color: var(--gray-alpha-100)` and `inset 2px 0 0 var(--gray-1000)` on the first cell. `src/Entity.d.ts` has no `current` or `selected` prop. `D:Menu` and `D:CommandMenu` describe highlighted items but expose no list-row component.
- **Verdict:** `fits with a prop or variant` (`TableRow current`); in the table above. The cursor tint differs (`gray-alpha-200` here, `gray-alpha-100` in `src/Table.css:55`) and there is no marker.

## Open questions

Each one ends with the decision taken on it (ADR 0017).

1. **Search-queued strip** (`web/src/shell/Shell.tsx:436-455`): `D:Note` says "Notes are not dismissible: if the message can go away, it belongs in a Toast or a ProjectBanner"; `D:ProjectBanner` says "It isn't dismissible"; `D:Toast` says "never put navigation in a toast", while this strip carries a "See the search" button that navigates and a Dismiss button. **Decision:** A Toast without navigation; the strip and its "See the search" button go.
2. **Library list** (`web/src/library/Library.tsx:234-272`): `Table` `current` and `Entity` both fit the row; `Entity` has no current state, and the hand-built element is a `role="listbox"` with `role="option"` rows, not a table. **Decision:** Entity rows with the new Entity `current` (library change, ADR 0017).
3. **Version rows** (`web/src/library/VersionRows.tsx`): `Entity.List` (card with dividers) or `Table` (columns); neither doc describes the five-column grid that stacks on a narrow container, and Kestrel draws `border-y`, not a card. **Decision:** An `Entity.List` card whose rows stack on a phone; the design's card replaces `border-y`.
4. **Fixed-size Skeletons** (`web/src/library/TitleDetail.tsx:41-48`): `D:Skeleton` says "Match the final content's size exactly ... Never show a generic block" and that Skeletons are hidden from screen readers; the page wraps them in `role="status" aria-label="Loading"`. **Decision:** Keep Skeletons, size them to the final content, and announce loading outside them.
5. **Inline confirmations** (`web/src/library/DeleteFiles.tsx:68-119`, `web/src/library/MoveTitle.tsx:20-56`): `D:Modal` calls itself "a blocking dialog" and also lists `inline` ("render in place"). Separately, `D:DestructiveActionModal` opens "submit stays disabled until the person types a verification phrase exactly", while `src/DestructiveActionModal.js:10-12` leaves the gate off when `verificationPhrase` is absent, which is how `web/src/library/ManageVersion.tsx:29-45` and `web/src/cleanup/Cleanup.tsx:137-147` call it. **Decision:** `Modal inline` for both. The verification-phrase behaviour of `DestructiveActionModal` was not decided here.
6. **Loading states:** `D:Spinner` says "Pair it with text such as 'Loading…'"; `D:Skeleton` says "For a table, use `loading` on Table"; `D:Entity` says "While loading, keep the row shape and put Skeletons in `left` and `Entity.Content`". Rows that show a Spinner with text in a table-shaped or list-shaped region: `web/src/library/ManualSearch.tsx:227-231`, `web/src/adoption/Finished.tsx:70-74`, `web/src/adoption/Adoption.tsx:321-324`. `D:Spinner` also says "Show it only after about 300ms"; whether Kestrel delays is unconfirmed. **Decision:** Table regions use `Table.SkeletonRow` with `aria-busy`. Entity lists keep their row shape, with Skeletons in the rows. Elsewhere, a Spinner with text, shown after about 300ms.
7. **FilterBar override** (`web/src/filter/FilterBar.tsx:48-54`): the comment waits for hyprsh/design#26; `QueryBar` `wrap` (default true) is documented at v0.11.0. Which of the four classes are still needed is unconfirmed. **Decision:** Remove the whole override and rely on `wrap`; verify the result at 390px.
8. **EmptyState `m-4 w-auto`** (five places, Requests and Log table): `size="small"` is documented but has no border, icon or heading; no margin prop exists, and `src/EmptyState.css` sets `width: 100%`. **Decision:** Remove the overrides; the wrapper carries the spacing.
9. **Needs attention rows** (`web/src/overview/NeedsAttention.tsx:152-168`): `D:Entity` says "Keep the right side to one or two controls. For more, use a single menu button"; rows carry `row.actions.length` buttons (unbounded in the code read). **Decision:** The first action stays a Button and the rest go into a `DotsMenu`.
10. **Spinner prefix on clickable Buttons** (`web/src/shell/Shell.tsx:467`): `D:Button` says `loading` makes the button "busy and can't be pressed twice"; the top-bar indicator is pressable. **Decision:** Cleanup uses `loading`. The top-bar indicator becomes a tertiary Button with a StatusDot `info` prefix and stays pressable.
11. **Notices text** (`web/src/about/About.tsx:114`): `D:Code` block is for "a short unhighlighted listing"; `D:CodeBlock` is for "multi-line, syntax-coloured source". The text is long and scrolls. **Decision:** `Code block`.
12. **Cursor tint:** `NavRow` uses `bg-gray-alpha-200`; `src/Table.css:55` uses `gray-alpha-100` plus a 2px marker; `D:Table` calls the tint "the same ... as a highlighted menu item". **Decision:** The design's tint wins: Table's `gray-alpha-100` and 2px marker, given to Entity through `current`.
13. **`blue-*` utilities:** `project/README.md:25` says the accent is reached "through `accent-100`…`accent-1000` ... never through `blue-*` directly". Kestrel uses `blue-*` at `web/src/upcoming/Upcoming.tsx:269-274`, `web/src/library/EpisodeMatrix.tsx:27,339`, `web/src/library/TitleStatus.tsx:12` and `web/src/overview/HealthStrip.tsx:30`.
